# YERA static website

A redesigned static site preserving YERA's original logo, published content and media, fetched directly from the live website. Built with Astro, React islands, Tailwind CSS 4 and local shadcn/ui primitives. Fonts and original images are hosted locally. Reading pages requires no JavaScript or WordPress server.

For the GitHub Pages handoff, start with [PUBLISHING.md](PUBLISHING.md).

## Editorial design

The homepage leads with recent writing, followed by topics, the original mission and recent events. The full current board appears on About. Source Serif 4 headlines and reading text pair with Manrope navigation, warm paper backgrounds, forest charcoal text and muted blue accents and navy buttons. Soft sage and sand sections, rounded imagery and original member portraits give the site a more welcoming character.

The library supports topic, collection and format filters. Topic assignments are title-based browsing metadata in `src/lib/topics.ts`; edit those rules as the archive grows. Article contents, reading times and linked references are generated by `src/lib/editorial.ts` without changing the imported source records. React islands remain available for future calculators and graphs.

## Develop and verify

Use Node 24 LTS (`.nvmrc`).

```sh
npm ci
npm run dev
npm run build
npm run preview
```

The deployable output is `dist/`. The build checks Astro templates and TypeScript. For browser tests, start a preview server, then run:

```sh
npx playwright install chromium
PREVIEW_URL=http://localhost:4321 npm test
node scripts/verify-migration.mjs
```

Set `BROWSER_EXECUTABLE` if using an already-installed Chromium. Browser tests expect the original imported dataset. The migration verifier compares all 180 article/event bodies and references with captured live-source records, verifies media checksums and checks local output links.

## Content

- `src/data/site.json`: complete imported publication, event and people data.
- `migration/source/`: original responses and frontend evidence.
- `migration/assets.json`: asset origins and hashes.
- `public/wp-content/uploads/`: original media, copied unchanged.
- `public/brand/`: original logo and favicon.
- `src/components/`: shared page content and layouts.
- `src/styles/global.css`: design tokens and responsive styling.

`npm run build` reads checked-in data only; it never needs the original site. To intentionally recapture published content, run `node scripts/fetch-source.mjs`, then `node scripts/import-content.mjs`, review changes, rebuild and rerun verification. Importing overwrites `src/data/site.json`; preserve any new hand-authored material separately.

The English and main article collections contain 8 and 126 records respectively. Existing duplicates and original languages are intentionally preserved. All source article/event slugs and frontend `?id=` links are supported. See [MIGRATION.md](MIGRATION.md) for the inventory, verification and the contact-form behavior change.

## Future calculators and charts

React and shadcn/ui are configured through `components.json`, `@/*` imports and theme variables. The current article search uses the included Button and Input components. Add more primitives when needed:

```sh
npx shadcn@latest add slider card chart
```

Build a calculator as a React component and embed it in an Astro or MDX page:

```astro
---
import EnergyCalculator from '@/components/EnergyCalculator';
---
<EnergyCalculator client:visible />
```

The component above is an example for future work, not an included calculator. `client:load` enables immediate interaction. MDX support is installed for future content in `src/pages/`. The shadcn chart component adds Recharts when needed. Calculations and graphs can run entirely in the browser on either static host.

## Cloudflare Pages

Connect the repository with:

| Setting | Value |
| --- | --- |
| Build command | `npm run build` |
| Output directory | `dist` |
| Node version | `24` |
| `SITE_URL` | `https://yera.be`, or the intended deployment origin |
| `BASE_PATH` | `/` |

No Cloudflare adapter, Worker or runtime binding is required. Configure the custom domain in Pages when ready.

## GitHub Pages

Choose **GitHub Actions** under repository Settings → Pages. Run the included **Deploy to GitHub Pages** workflow manually. The workflow reads the configured origin and base path, supporting both a repository subpath and a custom domain.

Test a repository subpath locally with:

```sh
SITE_URL=https://example.github.io BASE_PATH=/yera-website/ npm run build
```

No deployment or DNS changes have been performed. To add automatic deployment later, add a push trigger for your production branch.

References: [Astro on GitHub Pages](https://docs.astro.build/en/guides/deploy/github/), [Astro on Cloudflare](https://docs.astro.build/en/guides/deploy/cloudflare/), [shadcn/ui with Astro](https://ui.shadcn.com/docs/installation/astro).
